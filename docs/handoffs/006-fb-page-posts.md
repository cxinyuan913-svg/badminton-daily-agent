# 交接單 006：FB 粉專貼文草稿

2026-10-01，claude.ai 撰寫。Raymond 定案（16:07）：
- **發文方式 A**：只產草稿，推到 Discord 新的「粉專」頻道，Raymond 看過自己貼。**不串 Meta API、不自動發文。**
- **內容 C**：比賽日發台灣戰報，有好故事就寫故事。

前置：notes 15:40 寫作規則、交接單 005 故事引擎（故事候選、推測標註、待查清單共用）。

## 1. 每天選哪一種（只產 1 則）
依序判斷，第一個成立的就用：
1. **台灣戰報**：昨天（台灣時間）有推送層級賽事、而且有台灣選手出賽。內容：台灣選手昨天的結果（含「差一點」的場次）＋今天的對手與台灣時間（用 `preview.py` 的資料）。當天故事分數最高、而且跟台灣有關的那個，濃縮成一段放進去。
2. **故事貼文**：昨天有比賽、但沒有台灣選手（或台灣選手已全部止步）→ 用 005 分數最高的故事，寫成貼文版。
3. **冷知識**：沒有比賽的日子，從下面輪流挑：
   - **歷史上的今天**：資料庫裡同月同日（2017 年起）的重要決賽或台灣選手好成績，例如「3 年前的今天，○○拿下××冠軍」。
   - **宿敵／宰制**：005 的 `rivalry`、`domination` 候選，挑最近 3 個月內有交手的。
   - **規則與賽制**：從 `config/trivia_rules.md` 挑（先建一份 10 條，由 claude.ai 寫初稿、Raymond 審過才用；在那之前跳過這類）。
   - 週二若有官方排名更新，優先寫排名變化（台灣選手升降＋背後的戰績）。

## 2. 貼文格式
- 第一行就是鉤子（數字或反差），不要用「大家好」開場。
- 正文 150–400 字，短段落（每段 1–3 句），可以用少量表情符號（每則 ≤ 5 個）。
- 結尾一個互動問句。
- hashtag 3–5 個：`#羽球` 加上相關選手或賽事（中文）。
- 附「建議配圖」一行：用哪種字卡版型＋要填的欄位（版型由 claude.ai 設計中，先用文字描述）。
- 有新聞來源的事實，附「建議放在第一則留言的連結」（標題＋網址），不要塞在正文。
- 推測句標「⚠️推測」，最後附「待查清單」；**這兩項只給 Raymond 看**，推送格式要清楚分隔「貼文正文」和「給你的備註」，讓他可以整段複製正文。

## 3. 時間與輸出
- 每天 **台灣時間 07:00** 產生（主機 systemd timer，UTC 23:00；本機階段用 Windows 排程）。
- 推到 `DISCORD_WEBHOOK_FBPAGE`；**沒設定時只寫檔** `data/posts/YYYY-MM-DD.md`（目前 Raymond 還沒給 webhook）。
- 模型：`routine`（Sonnet），推理強度照 15:20 實驗結果；計入每日預算（`LLM_DAILY_BUDGET_USD`），超過就跳過並告警。
- 規則照舊：獎牌用語、譯名一致、事實檢查、推測標註。

## 4. 驗收
- 用 3 天資料各跑一次（dry）：亞運 9/26（台灣戰報）、亞運 9/29 決賽日隔天（9/30，台灣戰報或故事）、今天 10/01（冷知識，用歷史上的今天），全文貼 status.md。
- 列每則費用。
