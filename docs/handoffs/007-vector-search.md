# 交接單 007：新聞向量庫與混合檢索（本機）

2026-10-02，claude.ai 撰寫。Raymond 同意 CLI 在 status.md 提的設計（10-02 07:20 選 6A）。💻 本機做。

## 目標
故事引擎與粉專的【新聞】區，從「關鍵字比對」升級成「語意＋關鍵字混合檢索」，能回答「這位選手最近有沒有傷病、換教練、受訪說了什麼」。

## 設計（照 CLI 提案）
- 模型：`BAAI/bge-m3`，fp16 跑在 GTX 1650（4 GB VRAM），batch 8–16、最長 512 token；沒有 GPU 時自動退回 CPU。
- 切段：400–500 字、重疊 50 字；每段記 url、段號、來源、日期、提到的選手 ID（用中英文名與暱稱比對）。
- 儲存：另開 `data/vectors.db`（不進 `brief.db`，**不備份**：可以從 `brief.db` 的新聞全文重算）。
  - `chunks` 表、`sqlite-vec` 的 `vec0(embedding float[1024])`、`FTS5`（`trigram`）。
- 檢索：FTS5 BM25 前 30＋向量前 30 → RRF 合併 → 依日期與選手過濾 → 回傳前 k 段（附 url、日期、來源）。
- 增量：每次新聞收集後，只處理新文章；模型只在有新文章時載入，處理完釋放 GPU 記憶體。
- 重建：`python -m brief.vectors --rebuild` 從頭重算。

## 接到現有流程
- 故事引擎與粉專的【新聞】區：先用選手 ID 過濾、再用「選手名＋故事類型」當查詢（例如「CARNANDO MARTHIN 拆夥 重組」），取前 3 段當素材，附出處。
- 新聞摘要不需要向量庫，維持現狀。
