## 2026-10-01 推理強度與成本的取捨實驗
- **問題**：Console 顯示一天 US$3.48，幾乎都是腳本試寫的 Opus 輸出 token。每次呼叫平均輸出 5,000–6,000 token，但一份腳本實際只要約 1,000 token；差額是 `effort: high` 的內部推理。
- **做法**：同一批素材（兩個故事），Opus high／medium／low 與 Sonnet medium／low 各跑一次，記輸出 token、費用、事實檢查、重試。第一輪後依失敗原因修提示詞與檢查器，再跑第二輪。
- **數字**（第二輪）：Opus low 兩個故事都**一次通過**、每支 US$0.050–0.057、輸出約 2,000 token；Opus high 輸出 6,500–8,000 token、US$0.155–0.182，而且在 max_tokens 4000 下會被截斷（推理吃掉輸出額度）；Sonnet 便宜（US$0.03）但 4 次都沒過（超字數、自算數字）。結論：**更多推理不等於更好的稿**，這類「照事實清單寫短文」的任務 low 最好。
- **校正**：本機估算與 Console 差 13.6%，逐筆累加找到 Console 是在 02:52 UTC 讀的（當時累計 US$3.482，與 Console 的 3.48 一致），定價表本身正確。
- **commit**：320438e、314939a

## 2026-10-01 事實檢查器自己的漏洞：日期被當成比分
- **問題**：粉專貼文寫「排名比對手低 26 名」（68−42，模型自己算的），事實檢查卻放行。
- **發現**：逐步重現檢查流程，發現比分正規式把事實清單裡的日期「2026-10-01」讀成比分 26-10、10-01，於是 26、10 變成「查得到的數字」。
- **解決**：比分前後不能接數字或連字號；另外數字比對忽略前導零（「01」＝「1」）。兩個都加回歸測試。這個漏洞存在於今日重點、腳本、貼文共用的檢查器，修一處三處都受惠。
- **commit**：見本日最後一個 commit

## 2026-10-01 測試讀到正式設定、真的呼叫了付費 API
- **問題**：把 `.env` 的腳本開關改成 `dry` 後，watch 的單元測試跑完整流程時讀到開關，真的呼叫 LLM API，還把檔案寫進正式輸出資料夾。
- **發現**：測試時間從 4 秒變成 3 分多鐘，用 `pytest --durations` 找到是 watch 的 3 個測試。
- **解決**：`tests/conftest.py` 加 autouse fixture，所有測試一律看不到腳本開關與 webhook、輸出寫到暫存資料夾。教訓：功能開關從「預設關」改成「開」的那一刻，所有沒有隔離設定的測試都會跟著變。
- **數字**：測試 172 個回到 4.2 秒。

## 2026-10-01 腳本事實檢查擋下「沒有獎牌的銀牌」與一份假陽性
- **問題**：試寫腳本把台北公開賽（Super 300）的亞軍寫成「混雙銀牌」「好幾面銅牌」。World Tour 沒有頒獎牌，但素材把四強寫成「四強（銅牌）」，模型照著寫。
- **發現**：推到腳本頻道後重讀時發現；當時的事實檢查只比數字和名字，不管用詞。
- **解決**：名次用詞依賽事層級決定（只有奧運、世錦賽、綜合運動會、洲際錦標賽等才寫金銀銅）；檢查器加一條「這站沒頒獎牌就不能出現獎牌字眼」；推更正訊息。同一輪也發現爆冷檢查的假陽性：「世界第 71 爆冷擊敗世界第 5」只寫排名、沒寫名字，原本會被擋，改成兩個排名都對得上同一場規則判定的爆冷就放行（`#7` 不會被 `#71` 矇混，有測試）。
- **數字**：試寫 8 份，事實檢查擋下 1 份（台北公開賽快報，4 次都沒過，不推），另外促成上面兩項修正；全部試寫加驗收約 US$3.5。
- **commit**：9340ecd

## 2026-10-01 腳本只用官方排名
- **問題**：2019 以前的排名大多是自行重建的估算值。日報可以標「（估算）」，但口播腳本念出來就是事實。
- **解決**：腳本的事實清單只放官方排名；估算或查不到的就不寫排名，排名相關的故事規則也跟著不觸發。測試用 2018 全英賽：混雙、女雙（沒有官方週）沒有任何排名，男單（有 97 週官方資料）照常寫。
- **commit**：9340ecd

## 2026-09-30 照 BWF 規章重建世界排名，再改用官方歷史排名
- **問題**：排名 API 只保留約 60 週，2025-08 以前的比賽無法判斷「爆冷」。
- **解決**：照 BWF 排名規章（PRE2018／2018 新制／2024 第 17 週修正）從賽果重建每週排名：輪空、資格賽、lucky loser、WTF 小組賽、團體賽 §7.2 平均分、§2.2 下一屆到期、洲際分組。
- **數字**：5 個項目的官方前 10 名，**95.5–99.2%** 的估算誤差在 2 名以內；驗證中找到 **7 個系統性錯誤**並修正，前 50 名的準確率提高 5–9 個百分點（`docs/ranking-validation.md`）。
- **轉折**：之後在選手頁找到官方歷史排名接口（`player/ranking/publication/weeks`），2019-01-15 起 5 項完整，改用官方資料；重建保留作驗證與方法展示。2019 以前排名表 API 固定回 500，那段期間才用估算。
- **commit**：328f01e、6dcac34、e49bc26、d156ddf、76748ec、6e20820

## 2026-09-30 LLM 捏造團體賽比分 → 比分整組比對
- **問題**：「今日重點」寫出「印尼 3–2 中國」，但當天根本沒有這場團體賽。
- **發現**：原本的檢查把數字拆開比對，3 和 2 都能在別的比分裡找到，所以沒被擋。
- **解決**：比分改成整組比對（正反順序皆可，敗方角度會倒過來寫）；輸出出現「更正」「以下是」等自我修正字眼或多段落就整段不採用；這次捏造的輸出變成回歸測試。後來加上「爆冷只能用在規則判定的場次」。
- **commit**：fe8b045

## 2026-09-30 模型分流與費用紀錄
- routine（每天、量大：今日重點、新聞一句話、暱稱）用 Sonnet；heavy（推理：腳本、分析）用 Opus。可用 `.env` 換模型。
- 每次呼叫記入 `llm_call`（用途、實際回應的模型、token、估算費用）。伺服器端 fallback：拒答時由 API 改用其他模型。
- **數字**：日報類每月約 US$1（2026-09 實測 11 次呼叫 US$0.095）。腳本一站決賽日約 US$0.6–0.8，所以加了開關、每週費用列與每日告警。
- **commit**：3b7ce49

## 2026-09-30 每站「當地當天打完就發」
- **問題**：固定時間發日報，會遇到時差（歐洲賽事半夜才打完）和延賽。
- **解決**：`brief.watch` 每 30 分鐘檢查，每站當地當天全部打完就發；到當地隔天 03:00 還沒打完就保險發送，標出未完成場次，之後打完的併到下一天。明日看點用隔天賽程，換成台灣時間。連續抓不到就推告警。
- **commit**：dbb3f9b、e50c3db
